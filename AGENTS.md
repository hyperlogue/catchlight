# Catchlight

Catchlight is a Rust stack for 2.5D character animation by mesh deformation.
The core runs on Linux, Windows, macOS, iOS, Android, and browsers. Windows is
a tier-1 runtime target; browser rendering supports WebGPU and WebGL2.

## Project boundaries

- The editor is web-first: React over a wasm replica. The desktop egui editor
  (`crates/catchlight-editor/`) is frozen; bug fixes only.
- The editor owns the model; the browser holds a replica updated by the
  backend. Reads are synchronous against that replica. A drag commits once,
  holding its scratch until the committed revision arrives.
- Logic a native editor would also need belongs in Rust. `packages/core/`
  holds web-platform glue; `packages/react/` exposes hooks and unstyled parts;
  `packages/editor/` assembles them with the default theme under
  `@layer catchlight`.
- `.clm` is the only model load format. Inochi2d import is a one-time conversion
  in `catchlight-import-inx`, which depends on core, never the reverse.
- `catchlight-cli` operates on model files and never depends on the editor
  server, protocol, or their clients. Its file operations preserve encoded
  texture bytes without decoding images. New inspection tools belong in CLI
  subcommands, including replacements for the removed `mip-compare`,
  `param-sweep`, and `rig-dump` examples.
- The editor-server Unix socket is permanent Linux-only dev/agent tooling.
  The editor server also runs in-tab through wasm or behind HTTP locally.

## Task-specific references

- For domain terminology, use [CONTEXT.md](CONTEXT.md).
- For behavior changes, consult the affected module's `//!` documentation or
  TypeScript module comment. Document new invariants beside the code that
  enforces them. Keep this file focused on repo-wide constraints rather than
  duplicating the crate map, module invariants, or command help.

- For model-file operations, use `cargo run -p catchlight-cli -- --help`.

- For dependency or lint changes, the policy and rationale live in

## Generated files

- `packages/wasm/` is generated by `cargo xtask build-wasm [--debug]`; never
  edit or commit it. Build it before web typechecking or bundling.
- Rust wire types are authoritative for `packages/core/src/protocol.gen.ts`
  and `python/catchlight/protocol_gen.py`. Regenerate both with
  `cargo xtask generate` and commit the results when the protocol changes.
  `cargo test -p xtask -- --skip fixtures::` checks generation and command
  classification.

## Development and validation

The Nix dev shell is normally active through direnv. If tools or runtime
libraries are missing, use `nix develop -c <command>`; change the environment
in `nix/shell.nix`.

Carry the requested change through implementation, relevant validation, and
commit. Local builds, tests, regeneration, and fixes to failures caused by the
change are part of that work and need no separate confirmation. Report any
checks that remain blocked.

Choose checks for the affected behavior. The exact CI commands and build
prerequisites live in [.github/workflows/ci.yml](.github/workflows/ci.yml);
the full Rust test suite (`cargo test --workspace`) is local-only. Start Rust
tests with the affected crate or test; broaden when the change crosses shared
boundaries or a failure warrants it. Documentation-only edits need reference
and diff checks.

- When adding or moving compile-time assets (`include_str!`, `include_bytes!`,
  shaders), check the source filter in [flake.nix](flake.nix) and build the
  affected Nix package. Cargo builds from the checkout can pass with assets
  that Nix excludes.
- Render fixtures and baselines use Git LFS; fetch the objects before render
  suites. The dev shell supplies lavapipe for machines without a hardware GPU.
- For visual comparisons or intentional baseline updates, use the harness
  documentation in `crates/visual-tests/src/lib.rs`. Frame and physics
  baselines are documented in `crates/catchlight-core/tests/evaluated_frame.rs`
  and `crates/catchlight-core/tests/physics_trajectory.rs`.
- For browser integration checks, `apps/site/e2e/run.ts` and
  `apps/site/e2e/drive.ts` document the built-site, backend, browser, and
  GPU-tier requirements.
- Tests needing the private model at `example_models/reference/` and timing
  measurements are ignored with reasons in their attributes. Run a relevant
  ignored test with `-- --ignored` when its prerequisites are available.

## Commits

- Stay on the current branch unless asked otherwise. Commit completed,
  validated work before ending, unless the user requests uncommitted changes.
- Before staging, run `git diff --cached --name-only`. If it contains work you
  did not stage, leave it alone and recheck after 5s, 10s, then 30s. If it is
  still staged, stop and ask the user; never commit another committer's index.
- Stage and commit only your changes. If staging or committing hits a blocker,
  pause and ask. Never amend or rewrite commits unless explicitly requested.
- Subject: `<scope>: <imperative summary>`, lowercase, no trailing period,
  fewer than 72 characters. Add a body, wrapped around 72 columns, only when
  the reason is not clear from the subject and diff.
