# catchlight (Python)

A blocking client to `catchlight-editor-server`, and the editor protocol it
speaks. Pure Python, no runtime dependencies, no Rust linked: the server's
reader is the only validation there is, which is the point — a model this
package writes is a model the editor wrote.

```python
import catchlight

with catchlight.launch() as server:
    client = server.client()
    session = client.new("Doll")
    part = client.add_part(session, name="Body")
    client.add_texture(session, part, "body.png")
    client.send(catchlight.MeshAuto(session=session, node=part))
    client.save_to(session, "doll.clm")
```

## The pieces

| Module | What it is |
| --- | --- |
| `protocol_gen.py` | Generated wire types. Never edited by hand. |
| `transport.py` | One `request` interface, two doors: the Unix socket and HTTP + WebSocket. |
| `server.py` | `launch()` starts an editor and owns it; `connect(url, token)` attaches to one it does not. |
| `client.py` | `Client.send` for any command, plus the handful of round trips that are more than one call. |

`protocol_gen.py` is generated by `cargo xtask generate python` from
`crates/catchlight-editor-protocol` and committed; `cargo test -p xtask` fails
if it has drifted. Do not edit it — change the Rust types and regenerate.

## Two doors

`launch()` starts a server on a socket inside a fresh `0700` temp directory.
That directory mode is the whole of its access control, so there is no token,
and the socket never collides with the editor a person already has open. On
exit the process is terminated, killed if it lingers, and the directory
removed.

`connect(url, token)` attaches over the server's HTTP door instead — the one a
browser tab uses — for an editor something else is running. It never stops what
it did not start. The URL must name loopback: the token travels in clear text.

What differs between them is where the bytes are. Over the socket the editor
reads the very filesystem the script is on, so a texture is a path and
`save_to` is a save. Over HTTP the editor's store is somewhere else, so a
texture is staged with `PUT /files/…` and then named, and `save_to` fetches the
document and writes it here. `Client` picks by transport; a script reads the
same either way.

Events only exist on the HTTP door. The socket carries request and reply, and a
blocking caller learns its document moved from the `rev` on its own reply —
`client.revision(session)`.

## Commands

`Client.send` takes any command in the protocol and returns its reply body,
raising `ProtocolError` with an `ErrorCode` if the editor refused it. The
command's own `KIND` says what sending it does: `document` moves the session's
revision, `presence` and `scratch` move nothing, and the two query kinds read.

```python
from catchlight import MeshAuto, AutoMeshGrid, NodeTree

client.send(MeshAuto(session=session, node=part, mode=AutoMeshGrid(cols=4, rows=3)))
tree = client.send(NodeTree(session=session))
```

## Tests

```
cargo build -p catchlight-editor-server
cd python && uv run pytest -q
```

Each test launches its own server. `launch()` finds the binary from its
`binary` argument, then `$CATCHLIGHT_EDITOR_SERVER`, then `PATH`, then this
workspace's `target/debug` build — which is why `cargo build` above is the only
setup. One test waits out the editor's 30 s socket timeout for real; skip it
with `-m "not slow"`.

Unix-only, because the socket is.
